# 2026-06-17 회의록

## 1. 회의 목적

현재 Flex-log 프로젝트는 백엔드 CRUD 기능과 AI 소비 분석, 금융상품 추천 기능까지 일부 구현된 상태이다.
하지만 실제 사용자가 서비스를 어떤 흐름으로 이용하는지, 각 화면이 어떤 순서로 연결되는지 명확하지 않은 문제가 있었다.

이에 따라 이번 회의에서는 전체 서비스 흐름을 다시 정리하고, 이를 기반으로 와이어프레임을 설계하였다.
이후 개발 방향은 와이어프레임에 맞춰 백엔드와 프론트엔드 구조를 정리하고, UI/UX 완성도를 높이는 것으로 결정하였다.

---

## 2. 현재 구현 상태

현재까지 구현된 주요 기능은 다음과 같다.

* 백엔드 기본 CRUD
* 회원 관련 기능 일부
* 소비 로그 관련 기능 일부
* AI 소비 분석 기능
* 금융상품 추천 기능
* 금융상품 데이터 활용 구조 일부

다만 기능 단위 구현은 진행되었지만, 실제 서비스 페이지 흐름과 사용자 경험이 명확하게 연결되지 않아 전체 구조 재정리가 필요하다고 판단하였다.

---

## 3. 주요 논의 내용

## 3.1 서비스 흐름 재정리

Flex-log는 단순한 가계부가 아니라 소비 기록 기반 SNS 서비스이다.
사용자는 소비 내역을 게시글처럼 기록하고, 친구들과 피드에서 공유할 수 있다.
또한 기록된 소비 데이터는 AI 분석과 금융상품 추천, 자산 현황 확인 기능의 기반 데이터로 활용된다.

초기에는 소비 피드를 인스타그램 스토리처럼 보여주는 방식도 고려했지만, 소비 기록은 휘발성 콘텐츠가 아니라 분석에 활용되는 누적 데이터이므로 게시글형 피드가 더 적합하다고 판단하였다.

다만 소비 로그 작성 시에는 사진 안에 텍스트를 삽입하고, 텍스트 크기나 폰트 등을 설정할 수 있도록 하여 스토리형 편집 감성을 일부 반영하기로 하였다.

---

## 3.2 주가 데이터 활용 방향

보유 주식 현황 페이지 구현을 위해 주가 데이터를 어떻게 가져올 것인지 논의하였다.

논의된 내용은 다음과 같다.

* 주가 데이터는 실시간성이 중요하므로 WebSocket 기반 데이터 수신을 고려한다.
* 차트 라이브러리는 Lightweight Charts 사용을 검토한다.
* 기존 Chart.js보다 금융 차트 표현에 적합하다고 판단하였다.
* 국내 주가 데이터와 해외 주가 데이터는 한국투자증권 API 활용을 우선 검토한다.
* WebSocket 기반 실시간 데이터 연동은 구현 난이도가 높으므로, MVP 이후 확장 기능으로 단계적으로 구현하는 방향이 적절하다.

### 추가 논의 필요

회의 중 키움 API WebSocket 활용 가능성도 언급되었다.
따라서 추후 아래 항목을 비교해 최종 API를 결정할 필요가 있다.

* 한국투자증권 API
* 키움증권 API
* 실시간 WebSocket 지원 여부
* 국내/해외 주식 데이터 제공 범위
* 인증 방식
* 프로젝트 기간 내 구현 가능성

## 4. 와이어프레임 기반 화면 설계

## 4.1 초기 페이지

### 목적

서비스에 처음 접근한 사용자에게 Flex-log의 핵심 가치를 짧게 전달하고, 회원가입 또는 로그인으로 유도한다.

### 기능

* 프로젝트 소개 문구가 한 줄씩 등장했다가 사라지는 애니메이션 구현
* 마지막 문구 출력 후 회원가입 / 로그인 버튼 표시
* 로그인된 사용자는 메인 페이지로 자동 이동
* 비로그인 사용자는 회원가입 또는 로그인 페이지로 이동

### 예시 문구

* 소비를 기록하세요.
* 소비 습관을 돌아보세요.
* AI가 소비 패턴을 분석합니다.
* 나에게 맞는 금융 습관을 만들어보세요.

## 4.2 회원가입 / 로그인 페이지

### 기능

* 회원가입
* 로그인
* 로그인 성공 시 메인 페이지 이동

* 로그아웃 시 토큰 삭제

### 로그인 이후 공통 요소

* 뒤로가기 버튼
* 로그아웃 버튼
* 하단 네비게이션 바

## 4.3 메인 페이지

### 목적

친구들이 작성한 소비 로그를 피드 형태로 확인하고, 좋아요와 댓글을 통해 상호작용할 수 있는 공간이다.

### 방향

피드는 인스타그램 스토리처럼 넘겨보는 방식이 아니라 게시글형 피드로 구성한다.

이유는 다음과 같다.

* 소비 기록은 순간적으로 사라지는 콘텐츠가 아니라 누적 데이터이다.
* 월별 소비 분석과 AI 추천의 근거로 활용되어야 한다.
* 좋아요, 댓글, 피드 상세, 프로필, 마이페이지와 연결하기 쉽다.
* 무한 스크롤 방식으로 여러 소비 기록을 자연스럽게 확인할 수 있다.

### 기능

* 친구 피드 출력
* 피드 좋아요
* 피드 댓글 작성
* 좋아요 수 표시
* 댓글 수 표시
* 댓글 아이콘 클릭 시 피드 상세 페이지 이동
* 가능하면 피드 위에 모달 형태로 상세 페이지 표시
* 무한 스크롤 구현
* 페이지 새로고침 없이 다음 피드 로드
* 하단 네비게이션 바 제공

### 하단 네비게이션 항목

* 메인
* 프로필
* 친구
* 마이페이지

---

## 4.4 피드 상세 페이지

### 목적

하나의 소비 로그를 자세히 확인하고 댓글을 작성할 수 있는 페이지이다.

### 화면 구성

* 왼쪽: 피드 사진
* 오른쪽: 피드 설명, 좋아요 수, 댓글 목록

### 기능

* 피드 이미지 크게 보기
* 피드 설명 확인
* 좋아요 수 확인
* 총 댓글 수 확인
* 댓글 목록 확인
* 댓글 작성
* 본인 게시글인 경우 수정 / 삭제 가능

### 반응형 보완

PC 화면에서는 이미지 왼쪽, 설명과 댓글 오른쪽 구조로 구성한다.
모바일 화면에서는 이미지 상단, 설명과 댓글 하단 구조로 변경한다.

---

## 4.5 소비 로그 작성 기능

### 목적

사용자가 소비 기록을 게시글 형태로 작성하되, 사진 편집 기능을 통해 SNS적인 재미를 줄 수 있도록 한다.

### 기능

* 소비 사진 업로드
* 사진 안에 텍스트 삽입
* 텍스트 크기 설정
* 텍스트 폰트 설정
* 텍스트 색상 설정
* 텍스트 위치 조정
* 소비 카테고리 선택
* 금액 입력
* 상품명 입력
* 소비처 입력
* 메모 입력

### 보완 필요

소비 기록은 민감한 정보이므로 공개 범위 설정이 필요하다.

공개 범위 예시:

* 전체 공개
* 친구 공개
* 나만 보기
* 금액 숨김

* 피드 클릭 시 피드 상세 페이지 이동

## 4.8 마이페이지

### 목적

사용자의 소비 기록을 개인 대시보드 형태로 확인하는 공간이다.

메인 페이지가 친구 피드 중심이라면, 마이페이지는 내 소비 기록과 분석 중심으로 구성한다.

### 기능

* 캘린더 스타일 소비 지출 기록
* 특정 날짜 클릭 시 해당 날짜 소비 내역 표시
* 해당 날짜의 소비 카테고리 표시
* 금액 표시
* 상품명 표시
* AI 분석 페이지 이동 버튼
* 보유 주식 현황 페이지 이동 버튼

### 추가하면 좋은 정보

* 이번 달 총 소비 금액
* 가장 많이 쓴 카테고리
* 지난달 대비 소비 증감률
* 이번 달 소비 위험도
* 최근 AI 분석 요약

## 4.9 AI 분석 페이지

### 목적

사용자의 소비 로그와 재무 상태를 바탕으로 AI가 소비 패턴을 분석하고, 개선 방향과 금융상품을 추천하는 페이지이다.

### 분석 단위

* 일별 분석
* 주별 분석
* 월별 분석

MVP에서는 월별 분석을 우선 구현하고, 일별/주별 분석은 확장 기능으로 구현한다.

### 기능

* 소비 데이터 분석 피드백
* 카테고리별 소비 비중 분석
* 일/주/월 단위 소비 변화 분석
* 보유 주식 등락률 참고 분석
* 금융상품 추천
* 소비 개선 추천
* 종합 의견 제공

### AI 분석 결과 항목

* 소비 요약
* 주요 문제점
* 카테고리별 피드백
* 절약 팁
* 추천 행동
* 추천 금융상품
* 보유 주식 관련 참고 의견
* 종합 의견

### 금융상품 추천 방식

금융상품 API를 분석할 때마다 직접 호출하지 않는다.

추천 흐름은 다음과 같다.

1. 금융감독원 금융상품 API에서 상품 데이터를 가져온다.
2. 가져온 데이터를 fixture JSON으로 저장한다.
3. 다른 개발 환경에서는 fixture를 DB에 로드한다.
4. AI 추천 시에는 DB에 저장된 금융상품 데이터만 사용한다.
5. AI는 소비 분석 결과, 재무 프로필, 금융상품 후보를 바탕으로 추천한다.

## 4.10 보유 주식 현황 페이지

### 목적

사용자가 보유 중인 주식 현황을 시각적으로 확인할 수 있는 페이지이다.

### 기능

* 현재 보유 중인 주식 데이터 표시
* 보유 주식 목록 표시
* 종목별 보유 수량 표시
* 평균 매입가 표시
* 현재가 표시
* 평가 금액 표시
* 손익률 표시
* 종목별 그래프 표시

### 화면 구성

#### 왼쪽 사이드

보유 주식 종목 목록을 표시한다.

정렬 옵션:

* 종목명 가나다순
* 등락률순
* 보유금액순

#### 오른쪽 영역

선택한 주식 종목의 그래프를 표시한다.

표시 정보:

* 주가 그래프
* 현재가
* 등락률
* 보유 수량
* 평균 단가
* 평가 손익

### 기술 검토

* Lightweight Charts 사용 검토
* 한국투자증권 API 활용 검토
* WebSocket 기반 실시간 데이터 수신 검토

### 구현 우선순위

실시간 WebSocket 기반 주가 데이터 연동은 구현 난이도가 높으므로 후순위로 둔다.

우선순위는 다음과 같다.

1. 사용자가 보유 종목, 수량, 평균 단가를 직접 입력
2. 저장된 보유 주식 데이터를 화면에 표시
3. Lightweight Charts로 그래프 표시
4. 주가 API 연동
5. WebSocket 기반 실시간 주가 반영

## 7. 회의 결론

이번 회의를 통해 Flex-log의 전체 서비스 흐름을 다시 정리하였다.

기존에는 백엔드 CRUD, AI 분석, 금융상품 추천 기능이 개별적으로 구현되어 있었지만, 실제 사용자가 어떤 순서로 서비스를 이용하는지 명확하지 않았다.
이를 해결하기 위해 초기 페이지부터 로그인, 메인 피드, 프로필, 친구, 마이페이지, AI 분석, 보유 주식 현황 페이지까지의 흐름을 와이어프레임 기준으로 정리하였다.

또한 소비 로그는 스토리형 피드보다 게시글형 피드가 프로젝트 목적에 더 적합하다고 판단하였다.
소비 기록은 단순히 보여주고 사라지는 콘텐츠가 아니라, 분석과 추천에 활용되는 누적 데이터이기 때문이다.

이후 개발은 와이어프레임을 기준으로 백엔드와 프론트엔드 구조를 정리하고, UI/UX를 개선하는 방향으로 진행한다.
추가로 보유 주식 현황 기능과 주가 데이터 연동 기능을 확장 기능으로 구현할 예정이다.
